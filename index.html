第 00 章

零基础导读：3分钟看懂什么是 AI Agent 和 DSH

⏱️ 视频 00:00 - 05:00

很多朋友平时用过网页版的 DeepSeek 或 ChatGPT，你问它一个问题，它给你回复一段话。那为什么大家都在聊 Agent（智能体） 和 DeepSeek Harness (DSH) 呢？我们用一个最直观的生活比喻来解释：

🧠 1. 大模型 (LLM) = 军师的大脑

网页版聊天框里的 AI 就像一个被关在玻璃房里的智囊军师。他博古通今，能给你出主意、写代码草稿，但他没有手脚，没法帮你打开电脑文件夹，也没法替你把代码运行起来测试。

🤖 2. 智能体 (Agent) = 有手有脚的实习生

当我们给“大脑”装上双手和工具（比如允许它读写电脑文件、打开浏览器查资料、运行终端命令），它就进化成了 Agent。你只需说一句“帮我做个贪吃蛇网页并测试通过”，它就能自己动手干完。

🛠️ 3. Harness (DSH) = 实习生的现代化办公桌

Harness 英文原意是“挽具/装备挂具”。DeepSeek Harness (DSH) 就是 DeepSeek 官方打造的智能体运行底座——它给 AI 准备好了工位、工具箱、安全门禁和工作日志，让 AI 能稳稳当当地干活。

💡 一句话总结 DSH 是什么

以前你想让 AI 帮你自动改文件、跑程序，需要自己写一堆复杂的代码把大模型和电脑工具拼起来；现在有了 DeepSeek Harness (DSH)，DeepSeek 官方直接把这套“办公系统”做好了开源给你，你只需要填入 API Key（通行证），就能立刻拥有一个能操作电脑帮你干活的 AI 助手！

第 01 章

告别“会话焦虑”：为什么我们需要 SuperAgent？

⏱️ 视频 05:00 - 12:00

既然普通的 Agent（比如各类 AI 编程助手）已经能动手干活了，为什么视频里还要重点介绍 SuperAgent（超级智能体） 呢？因为普通的 Agent 存在三个让人头疼的“临时工痛点”：

对比维度 传统单会话 Agent（普通临时工） DSH SuperAgent（全职金牌团队）
触发方式 极度被动：算盘珠子拨一下动一下，你不找它说话，它永远在睡觉。 主动巡检：7×24小时盯紧项目仓库或飞书群，发现新任务或 Bug 自动接单处理。
多任务能力 Session（会话）焦虑：同时开 4 个窗口聊不同任务，人眼花缭乱，窗口之间还互相失忆。 并行分身：来 5 个任务就自动派出 5 个独立专员（Worker）在各自沙箱里并行干活。
记忆与变慢问题 上下文污染：在一个窗口里聊太久，AI 脑子越来越慢、还容易把 A 任务和 B 任务搞混。 脑手分离：主管只管派单不存垃圾草稿，专员干完活交完报告就销毁临时草稿，永远清爽飞快。
边界感 每做一步都要弹窗问你“行不行”，频繁打断你的注意力。 少占用人类注意力：不确定的事绝不乱改，干完活整理成标准工单（PR）等你喝着咖啡审批。
第 02 章

核心架构拆解：“一切皆插件”与“主管 + 专员”模式

⏱️ 视频 12:00 - 18:00

1. DSH 底座哲学：Everything is a Plugin（一切皆插件）

DeepSeek Harness 底层基于轻量级的 Cordis 微内核框架 构建。你可以把 DSH 想象成一套乐高积木底板：

  • 大模型大脑（LlmAdapter） 是块积木，随时可以切换 DeepSeek-V3、DeepSeek-R1 或其他兼容模型；
  • 工具手脚（Tools & Skills） 是块积木，比如读写文件、执行命令行、查网页；
  • 操作界面（Web UI / CLI） 和 聊天历史（Session Log） 也全都是积木插件！
  • 通过一个叫 Profile（配置文件套餐） 的清单，你可以一键决定今天给 AI 组装哪些积木。

2. SuperAgent 灵魂设计：Router（项目主管）+ Worker（执行专员）

为了解决多任务混乱，DSH SuperAgent 把一个臃肿的 AI 拆成了两层默契配合的职场角色。请看下方的直观架构流转图：

📊 DSH SUPERAGENT 全自动工作流转图（脑手分离设计）
📡 第一层：外部消息与事件源（Triggers） 人类日常沟通的地方
GitHub Issues有人提了新需求/Bug
Pull Requests代码审查意见与评论
飞书 / IM 机器人群聊里呼叫或派发任务
⬇ 实时监听 & 安全过滤（外部评论绝不能篡改系统权限） ⬇
👔 第二层：Router 主管层（全域协调员） 永远在线 · 绝不亲自写代码
意图判断与合并判断要不要接单、合并重复消息
创建工单 (Ticket)为每个独立任务建档追踪
统一对外汇报等专员干完活，统一回复人类
⬇ 按工单派发给独立隔离的专员（并行不串线） ⬇
👷 第三层：Worker 专员层（闷头干活的实干家） 独立文件夹 · 满配工具箱
Worker #1 (修 Bug)独立拉取代码 → 跑测试 → 提交修复
Worker #2 (写文档)阅读源码 → 补充 README → 提 PR
Worker #N (新功能)互不干扰，干完即回收临时环境
🎯 为什么说“Router 不配写代码的工具”是神来之笔？

如果主管（Router）自己下场去改代码、跑漫长的测试，那在它忙活的这 10 分钟里，其他人发来的消息就没人理了！所以 DSH 故意收走了 Router 的执行工具，让它只做轻量级的判断和派单，1 秒钟就能响应任何突发消息，脏活累活全交给后台的 Worker 专员去并行处理。

第 03 章

零基础环境搭建：3步拉起可视化 Web 控制台

⏱️ 视频 18:00 - 25:00

不要被“开源框架”四个字吓到！DSH 提供了免下载源码、一行命令直接启动网页界面的方式。哪怕你完全不懂编程，跟着下面 3 步也能在 5 分钟内跑起来。

1
检查并安装 Node.js 运行环境

DSH 是基于现代 Node.js 运行的。请确保你的电脑安装了 Node.js 22.19.0 及以上版本（或 Node.js 24+）。 打开你电脑上的终端（Windows 搜 PowerShell 或 CMD，Mac 搜 终端 / Terminal），输入以下命令检查版本：

Terminal / 终端 
# 查看当前 Node.js 版本（若显示 v22.19+ 或 v24+ 即为合格）
node -v

提示：如果提示找不到命令或版本太低，直接去 Node.js 官网 (nodejs.org) 下载最新的 LTS 安装包，像装微信一样一路点击“下一步”即可。

2
一行命令启动 DSH Web UI（零源码安装版）

不需要去 GitHub 下载几百兆的代码压缩包！直接在终端里运行下面这行神奇的命令，它会自动拉取官方最新版的 DSH 并启动网页控制台：

Terminal / 一键启动 Web 界面 
npx @deepseek-ai/dsh web

看到终端输出类似 Server listening at http://127.0.0.1:3080 的提示后，打开你的浏览器（Chrome / Edge / Safari），在地址栏输入并访问：
👉 http://127.0.0.1:3080

3
开发者可选：从源码克隆构建（如果你想自己改插件）

如果你是程序员，想深入研究 DSH 源码或编写自定义插件，可以使用 git 和 pnpm 从源码启动（纯新手可直接跳过这一步）：

Bash / 源码构建方式 
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web
第 04 章

Web UI 初体验：填入钥匙，让 AI 替你干第一票活

⏱️ 视频 25:00 - 31:00

打开 http://127.0.0.1:3080 后，你会看到一个非常清爽的现代化界面。新手第一次进来常问：“为什么下面的聊天输入框是锁住的，不能打字？” 别慌，只需完成以下两步初始化：

第一步：选择工作目录（Choose Workspace）

因为 Agent 是要帮你读写电脑文件的，你得先告诉它“在哪张办公桌上干活”。

  • 点击界面上的 Choose workspace（选择工作区） 按钮；
  • 在电脑上新建一个专门用来测试的空文件夹（比如 D:\dsh-demo 或 ~/dsh-demo）并选中它；
  • 选中后，底部的任务输入框就会立刻解锁！

第二步：配置 DeepSeek API Key（给大脑通电）

  • 点击左下角或侧边栏的 Settings（设置） → Models（模型）；
  • 填入你在 DeepSeek 开放平台 申请的 API Key（以 sk- 开头的一串密钥）；
  • 点击保存。密钥会被安全地保存在你本地的 $DSH_HOME/.credentials.yaml 中，无需重启服务，立即生效！

第三步：下达你的第一个实操指令！

现在回到主界面创建一个新会话（Session），复制下面这段话发给它，亲眼看看它是怎么自己动手的：

Prompt / 复制这段话发给 DSH 
请在当前工作目录下帮我创建一个单文件的个人番茄钟待办清单网页（index.html），要求界面美观现代，支持深色模式和倒计时提醒，写完后帮我检查一下代码语法有没有错误。

你会看到 DSH 在界面上一步步展示它的思考过程（Turn / Step）：它会自动调用文件写入工具创建 index.html，自动运行检查命令，最后向你汇报完成！

第 05 章

核心重头戏：部署 SuperAgent，开启 7×24 自动打工

⏱️ 视频 31:00 - 42:00

前面体验的是你在网页里跟它一对一交流。接下来就是本视频最精彩的部分：安装 dsh-superagent（超级智能体原型包），把它接入 GitHub 仓库或飞书，让它实现“不被 @ 也能主动帮你提 PR 干活”！

🖥️ SuperAgent 运行环境小贴士

因为 SuperAgent 需要在后台开启多个独立终端（使用 tmux）来管理并行干活的 Worker 专员，并调用 GitHub 工具（gh），官方推荐在 macOS、Linux 或 Windows 的 WSL2（Linux 子系统） 环境中运行完整版 SuperAgent，并确保已安装：git (>=2.32)、tmux、python3 和 gh (GitHub CLI >=2.48)。

方式 A：通过 DSH 插件命令挂载 SuperAgent

在 DSH 中，SuperAgent 本质上也是一个插件包（Bundle）。你可以通过命令行将它添加到指定的配置档案（Profile）中：

Bash / 安装 SuperAgent 插件包 
# 将 dsh-superagent 插件挂载到 web profile（或独立的 superagent profile）
dsh plugin --profile web add dsh-superagent

💡 视频避坑提示：首次挂载启动时如果看到终端返回 exit 3，千万别慌，这不是报错坏了！ 这是因为 SuperAgent 还在等待你完成初始的账号绑定与基础配置。

方式 B：超酷的“让 AI 帮你安装 AI”（交互式向导安装）

dsh-superagent-prototype 仓库做了一个极其贴心的设计：你完全不用自己去啃复杂的配置文件，仓库里的 SETUP.md 就是一份写给 AI 看的安装说明书！

Bash / 克隆原型仓库并交给 Agent 自动配置 
# 1. 克隆官方 SuperAgent 原型仓库
git clone https://github.com/deepseek-ai/dsh-superagent-prototype.git
cd dsh-superagent-prototype

# 2. 在 DSH 会话中直接对 Agent 发送下面这句话：
"Read SETUP.md in this repository and set up dsh-superagent with me."
# （请阅读本仓库的 SETUP.md 并一步步引导我完成 SuperAgent 配置）

发送这句话后，Agent 会自动检测你电脑上的软件环境，然后像聊天一样每次只问你一个简单问题（例如：“你想绑定哪个 GitHub 测试仓库？”），最后自动帮你生成所有隔离配置！

Web 面板三大核心控制页（Control Center）

启动后，在本地 Web 控制面板的 SuperAgent 侧边栏里，你会看到三个清晰的管理标签页：

🔗 1. Sources（消息源）

绑定你要监控的 GitHub 仓库、配置专属的 Bot 机器人账号，以及按需接入飞书机器人通道。

🛡️ 2. Policy（权限与策略）

设置白名单（Allowlist）：明确哪些同事的指令可以触发任务，以及设置自动接单的模式（off / observe / auto）。

⚙️ 3. Execution（执行空间）

管理 Worker 专员的独立工作目录、最大同时处理的工单数量（并发数），以及终端命令的安全规则。

第 06 章

安全第一：新手必看的“Observe 观察模式”与权限隔离

⏱️ 视频 42:00 - 46:00

很多新手听到“AI 自动改代码、自动提 PR”心里会打鼓：万一它曲解了别人的评论，把我的代码库改乱了怎么办？或者有陌生人在 GitHub 评论区注入恶意指令骗 AI 删库怎么办？

视频中特别强调了 DeepSeek 团队在安全上的两大硬核设计：

1. 铁律：上下文输入 ≠ 权限变更

在 DSH SuperAgent 中，外部路人的评论、不受信任的群消息，只会被当作普通的“参考文本”，绝不可能提升或改变 Agent 的执行权限。此外，系统会自动生成专用的命令垫片（worker-bin 和独立的 worker-gitconfig），确保 Worker 只能使用机器人自己的受限凭证，绝不会偷用你电脑上的个人最高权限账号。

2. 官方强烈推荐：先开 2 周 observe（观察模式）！

在 Policy（策略）设置中，SuperAgent 提供了三种自动接单模式。千万不要一上来就开全自动！

模式名称 形象比喻 具体行为说明 适用阶段
off（关闭主动接单） 只听点名 只有白名单里的人明确 @ 呼叫它时才干活，平时绝不主动揣测接单。 刚安装完的第一天调试期
observe（观察模式）⭐ 实习生写演练笔记 后台正常监控所有事件，并在日志里写下“如果让我干，我会接哪个单、派哪个专员怎么做”，但不真正动手改代码。 强烈推荐前 1~2 周使用！ 人工核对它的判断靠谱后再升级
auto（全自动模式） 正式员工全面上岗 看到符合条件的 Issue、报错或任务，自动建工单、派 Worker 改代码并提交 PR 等你审核。 观察期表现优异、团队完全信任后
第 07 章

进阶技巧：常用 CLI 命令速查表与避坑指南

⏱️ 视频 46:00 - 50:00

1. 遇到报错怎么办？先敲 dsh doctor！

如果在配置插件、网络代理、API 密钥或权限时遇到任何奇怪的报错，不要自己盲目乱改文件，优先在终端里运行官方自带的“全科医生诊断工具”：

Terminal / 一键健康检查与故障诊断 
dsh doctor

它会自动帮你体检 Node 版本、网络连通性、API Key 格式以及沙箱目录权限，并直接告诉你哪一项没通过、该怎么修。

2. DSH 黄金命令速查表（建议收藏）

Bash / DSH 常用命令大全 
# 1. 启动可视化 Web 界面（最常用）
npx @deepseek-ai/dsh web

# 2. 无界面模式（Headless）：在终端一句话让 AI 干完活自动退出
dsh --profile headless "帮我总结当前项目的目录结构并生成说明文档"

# 3. 安装社区或官方插件（支持 GitHub 仓库或 npm 包）
dsh plugin add github:owner/repo

# 4. 调试神器：打印当前最终生效的完整插件与配置树
dsh --profile web --dump-config

# 5. 叠加临时配置补丁（不破坏原有 Profile 配置）
dsh --profile web --patch ./my-custom-override.yaml
⚠️ 生产环境安全边界提醒

虽然 DSH 提供了 Sandbox（沙箱）、Approval（人工审批）和 Permission（权限控制）机制，但官方明确提醒：应用层沙箱并不等同于虚拟机级别的绝对硬件隔离。如果你让 SuperAgent 7×24 小时无人值守运行，强烈建议在独立的操作系统普通用户账号（Dedicated OS User）或 Docker 容器/测试服务器中运行，切勿在存有核心商业机密私钥的主力管理员账号下裸奔！

第 08 章

附录：新手高频“技术黑话”翻译词典 & 常见问题

📚 随时查阅

为了确保从来没用过 Agent 的朋友在看视频或看官方文档时不再一头雾水，这里把所有容易卡壳的英文词翻译成了大白话：

📖 什么是 Profile / Bundle / Cordis？（架构三剑客）
  • Cordis：DSH 底层的“插线板底座”，负责把各个功能插件通电连接起来。
  • Bundle（插件包）：打包好的一组技能套餐。比如“网页版套餐”包含界面和基础工具，“SuperAgent 套餐”包含主管和专员。
  • Profile（配置档案）：你给 AI 保存的“上岗身份卡”。比如你可以建一个叫 web 的档案平时自己聊天用，再建一个叫 superagent 的档案专门挂机干活，两者互不干扰。
📖 什么是 Session / Turn / Step / Context？
  • Session（会话）：你和 AI 开启的一个独立聊天窗口或任务档案。
  • Context（上下文）：AI 当前脑子里记住的“短期记忆”（包含你发的话、它读过的文件内容等）。
  • Turn（轮次）与 Step（步骤）：你发一句话、AI 最终回复你结果，这叫一个 Turn（回合）；在这一个回合里，AI 先后执行了“查看目录 → 读取文件 → 修改代码 → 运行测试”这 4 个动作，每个动作就叫一个 Step（步骤）。
